## 1. 上线目标

初版要打通一条最小但完整的生产链路：

```
运营登录后台
  → 编辑页面编排（草稿）
  → 编辑顶部导航 / 底部导航 / 站点配置
  → 发布页面
  → 官网 Nuxt SSR 通过渲染接口读取已发布内容
  → 访客浏览中英文页面、提交联系表单
```

初版完成后，`admin/` 与 `frontend/` 都不再依赖 mock / `localStorage` 数据。

**上线验收的最低标准**

1. 后台可以登录，未登录访问后台接口返回 `40100`。
2. 页面草稿可以保存、重新打开、发布、下架；发布后官网立即可读。
3. 顶部导航、底部导航、站点配置保存后，官网头部与页脚同步生效。
4. 中英文页面各自独立发布；另一语言未发布时返回 404 + `noindex`。
5. 官网页面、新闻 / 产品 / 案例列表（自定义卡片）与联系表单全部走真实接口；初版不做内容详情页。
6. 表结构与主文档一致，时间、ID、响应格式符合统一约定。

## 2. 范围

### 2.1 本期实现

| 模块 | 内容 |
| --- | --- |
| 认证 | 登录、登出、当前用户（Session）；后台接口只校验登录状态，不做角色 / 接口权限校验 |
| 页面编排 | 页面列表、新建、详情、保存草稿、删除、翻译、发布、下架 |
| 顶部 / 底部导航 | 菜单列表、菜单详情、整体保存；头部设置、页脚设置、站点配置读写 |

### 2.2 范围说明（含已实现与延后项）

| 项 | 处理方式 |

| 审计日志、发布记录界面 | `xqyun_publish_records` 照常写入；审计查询二期再做 |

| 审批流、发布全部语言、站点发布批次 | 二期 |
| CDN 清理、ETag / 缓存 | 初版直读数据库；流量上来后再加 |
| 留言 CSV 导出 | 已实现（按当前筛选条件导出） |
| sitemap.xml / robots.txt | 建议上线前补齐，列为 P1（见 3.6） |

### 2.3 前置假设

- MySQL 8 已按 `deploy/init.sql` 建好 `xqyun` 库。
- Redis 可选；初版限流可以先用进程内实现，多副本部署前再切 Redis。
- `frontend/` 与 `admin/` 的 `services/` 是唯一改接口的地方，页面与区块组件不动。
- 中英文在数据库统一使用 `zh-CN` / `en`；前台类型里的 `zh` 在 services 层映射为 `zh-CN`。
- 所有时间字段为 Unix 秒（`int64`），所有 ID 在 JSON 中传字符串。

## 3. 接口清单

> 初版不做角色与接口权限：后台接口只校验登录会话是否有效，不校验具体 URL / 方法权限。主文档中的角色与 URL 策略在二期接入，接口路径与响应结构保持不变。

### 3.1 认证

| # | 方法 | 路径 | 作用 | 鉴权 |
| --- | --- | --- | --- | --- |
| A1 | POST | `/api/v1/admin/auth/login` | 账号密码登录 | 公开 |
| A2 | POST | `/api/v1/admin/auth/logout` | 退出登录 | 公开（删除会话） |
| A3 | GET | `/api/v1/admin/me` | 当前用户 | 登录 |

- 管理后台登录会话由 hertz-contrib/sessions 写入 Redis（不建表），Cookie `xqyun_admin_session` 默认 TTL 12 小时；JWT 保留给后续前台用户。
- 登录失败需要限流；初版可按用户名 + IP 做简单的失败计数。
- 后台登录页 `/#/login` 已调用 A1（初始账号 `admin` / `123456`），会话由后端写入 HttpOnly Cookie，前端不保存令牌；图形验证码仍为前端生成与校验。
- 登录页已有图形验证码，但当前由前端生成与校验；生产环境的服务端验证码（下发 + 登录校验）不在初版范围，二期再补。

### 3.2 页面编排

| # | 方法 | 路径 | 作用 | 鉴权 |
| --- | --- | --- | --- | --- |
| P1 | GET | `/api/v1/admin/pages` | 页面列表，支持 `locale` / `status` / `keyword` / 分页 | 登录 |
| P2 | POST | `/api/v1/admin/pages` | 新建页面 | 登录 |
| P3 | GET | `/api/v1/admin/pages/:id` | 页面详情（当前草稿） | 登录 |
| P4 | PUT | `/api/v1/admin/pages/:id` | 保存草稿：路径、名称、SEO、区块 | 登录 |
| P5 | DELETE | `/api/v1/admin/pages/:id` | 软删除页面 | 登录 |
| P6 | POST | `/api/v1/admin/pages/:id/translate` | 创建 / 获取另一语言配对草稿 | 登录 |
| P7 | POST | `/api/v1/admin/pages/:id/publish` | 发布当前草稿，覆盖线上内容 | 登录 |
| P8 | POST | `/api/v1/admin/pages/:id/unpublish` | 下架：状态改为未发布，清空线上内容 | 登录 |

- `P4` 整体保存当前页面的草稿，区块的增删与排序都在前端完成后一次提交；不需要区块级 CRUD 接口。
- 页面状态只有 `draft` / `published`；发布用 `draft_content` 覆盖 `published_content`，`version + 1`。
- `P6` 复制区块结构，清空可翻译文本，保留图片与链接；目标语言已存在配对页面时直接返回。
- 初版不做乐观锁；同一页面多人同时编辑时后保存者覆盖前者，二期再补版本校验。
- 初版不做 `/preview-token`：后台预览通过 `GET /admin/pages/:id` 取草稿，再 `postMessage` 给 `preview.html`。

### 3.3 顶部 / 底部导航与站点配置

| # | 方法 | 路径 | 作用 | 鉴权 |
| --- | --- | --- | --- | --- |
| N1 | GET | `/api/v1/admin/menus` | 菜单列表 | 登录 |
| N2 | GET | `/api/v1/admin/menus/:code` | 菜单详情与菜单项 | 登录 |
| N3 | PUT | `/api/v1/admin/menus/:code` | 整体保存菜单项：排序、显隐、文案、链接 | 登录 |
| N4 | GET | `/api/v1/admin/settings` | 站点设置（含 `header` / `footer` / `brand`） | 登录 |
| N5 | PUT | `/api/v1/admin/settings` | 保存站点设置 | 登录 |

菜单编码固定三个：

| code | 用途 | 结构 |
| --- | --- | --- |
| `header` | 顶部导航菜单项 | 一级菜单，`parent_id` 为空 |
| `footer` | 页脚栏目与栏目内链接 | 顶级项是栏目，`children` 是链接 |
| `footer_bottom` | 页脚底部链接 | 一级链接 |

- 「增删改查」在后台界面内完成，保存时通过 `PUT` 整体提交当前菜单的全部条目；后端按 `id` 做 upsert，并删除本次提交中已不存在的条目。这样排序、父子关系和显隐在一次事务内完成，避免逐条接口造成顺序错乱。
- `settings.header` 负责公告条、顶部按钮、语言入口、吸顶；`settings.footer` 负责订阅区、联系入口、大字标、状态提示。链接结构仍只放在 `xqyun_menu_items`，避免两处都能改链接。
- 初版 `xqyun_settings` 的每个 key 都存完整双语 JSON（`locale = ''`），后台一次保存中英文；后续需要按语言拆分时，再写入 `locale = 'zh-CN'` / `'en'` 行覆盖。

### 3.4 表单留言

| # | 方法 | 路径 | 作用 | 鉴权 |
| --- | --- | --- | --- | --- |
| S1 | GET | `/api/v1/admin/submissions` | 留言列表，支持 `status` / `form_key` / `keyword` / 时间 / 分页 | 登录 |
| S2 | GET | `/api/v1/admin/submissions/:id` | 留言详情 | 登录 |
| S3 | PUT | `/api/v1/admin/submissions/:id/status` | 标记处理状态 | 登录 |

- 状态值沿用主文档：`new` / `processing` / `done` / `spam`。
- 列表默认按 `created_at` 倒序；后台列表与详情都读取 `xqyun_form_submissions`。
- CSV 导出已实现（按当前筛选条件导出）；批量操作初版不做。
- 后台页面入口：`/#/submissions`（侧边栏「线索 → 表单留言」）；已调用 S1–S3 读写 Go API。

### 3.5 官网公开接口

| # | 方法 | 路径 | 作用 | 调用方 |
| --- | --- | --- | --- | --- |
| W1 | GET | `/api/v1/frontend/render/page?path=&locale=` | 页面渲染聚合：页面 + 导航 + 站点 | 所有官网页面 |
| W2 | POST | `/api/v1/frontend/forms/{key}/submissions` | 表单提交，如 `contact` | 联系表单区块 |
| W3 | GET | `/ping` | 健康检查（已实现） | 部署 / 探活 |

- `W1` 是初版唯一的页面数据接口：服务端一次返回 `{ page, nav, site, collections }`。
- `W1` 只返回已发布页面；未发布或不存在返回 `40400`，前台输出 404 + `noindex`。
- `W1` 的 `alternates` 只包含已发布语言，供 hreflang 与语言切换使用。
- `collections` 初版固定返回 `{ news: [], products: [], cases: [] }`，保持响应结构稳定；列表数据全部来自页面区块的自定义卡片，后台不需要查询内容表。
- `W2` 校验必填项、邮箱格式与长度，做 IP 限流，完整内容写 `xqyun_form_submissions.data`。

**初版不实现的公开接口**（没有调用方或数据源）：

| 接口 | 不实现的原因 |
| --- | --- |
| `GET /api/v1/frontend/render/content` | 初版不做内容库与详情页，新闻 / 产品 / 案例没有详情数据源。 |
| `GET /api/v1/frontend/contents` | 列表使用页面区块的自定义卡片，不读取内容库。 |
| `GET /api/v1/frontend/categories` | 初版没有内容分类与筛选器。 |
| `GET /api/v1/frontend/site/config` | `render/page.site` 已聚合站点配置和头部 / 页脚设置。 |
| `GET /api/v1/frontend/site/nav` | `render/page.nav` 已聚合顶部与页脚导航。 |

> 这些接口保留在主文档中，等出现真实调用方（内容库、详情页、分类筛选、非页面级取数）时再实现；初版不做无人调用的接口。

### 3.6 P1：上线前建议补齐

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/sitemap.xml` | 已发布页面与内容的双语 URL，带 hreflang alternate |
| GET | `/robots.txt` | 根据 `settings.seo.allow_index` 输出 `index` / `noindex` 与 sitemap 地址 |

这两项不阻塞前后台联调，但会影响 SEO 上线质量；建议与公开接口同一阶段完成。

## 4. 关键接口契约

> 以下示例只补充主文档没有展开的请求体 / 响应体；字段定义与主文档一致。

### 4.1 登录

请求：

```json
{
  "username": "admin",
  "password": "********"
}
```

响应 `data`：

```json
{
  "expires_in": 43200,
  "user": {
    "id": "1",
    "username": "admin",
    "name": "管理员",
    "roles": [],
    "permissions": []
  }
}
```

- 初版不做角色与权限：`roles` / `permissions` 字段保留为空数组，前端不据此做按钮控制，后端也不做接口权限校验；二期接入 Casbin RBAC 后填充，`permissions` 为 `"METHOD 路由模板"` 列表（见 [权限控制方案](./权限控制方案.md)）。
- 登录会话不放在响应体，通过 HttpOnly Cookie（`xqyun_admin_session`）下发；服务端从 Cookie 读取，前端不可读取。
- 密码使用 bcrypt 加盐哈希校验，禁止明文落库；bcrypt 密码上限为 72 字节。
- 失败返回 `40100`，不区分「用户不存在」与「密码错误」。

### 4.2 保存页面草稿

请求体与主文档 §4.2 一致：

```json
{
  "path": "/about",
  "name": "关于我们",
  "seo": {
    "title": "关于我们 - 小鹊云",
    "description": "...",
    "keywords": ["小鹊云"]
  },
  "blocks": [
    { "id": "b_01", "type": "hero", "props": {} }
  ]
}
```

- `path` 在同一语言下唯一；冲突返回 `40900`。
- `blocks` 原样保存为 JSON，后端只校验类型是否为已知区块、必填字段是否为空。
- 保存接口只写 `xqyun_pages.draft_content`，不影响 `published_content`。

### 4.3 发布 / 下架

发布请求：

```json
{ "note": "更新首屏文案" }
```

发布响应：

```json
{
  "version": 4,
  "published_at": 1792375200
}
```

- 发布：`published_content = draft_content`、`version + 1`、`status = published`、写 `xqyun_publish_records`。
- 下架：`status = draft`、`published_content = NULL`、草稿保留。
- 只影响当前语言，不级联另一语言。

### 4.4 菜单详情与保存

`GET /api/v1/admin/menus/header` 响应 `data`：

```json
{
  "code": "header",
  "name": "顶部导航",
  "items": [
    {
      "id": "1",
      "parent_id": null,
      "label": { "zh-CN": "产品", "en": "Product" },
      "link_type": "page",
      "link_value": "/products",
      "target": "_self",
      "sort": 1,
      "visible": true
    }
  ]
}
```

`PUT /api/v1/admin/menus/header` 请求体：

```json
{
  "items": [
    {
      "id": "1",
      "parent_id": null,
      "label": { "zh-CN": "产品", "en": "Product" },
      "link_type": "page",
      "link_value": "/products",
      "target": "_self",
      "sort": 1,
      "visible": true
    }
  ]
}
```

- `id` 为空表示新增；后端返回保存后的完整 `items`。
- 页脚的栏目与链接使用同一结构：顶级项是栏目，子项 `parent_id` 指向栏目。
- `label` 必须是 `{ "zh-CN": "...", "en": "..." }`。

### 4.5 站点设置

`GET /api/v1/admin/settings` 响应 `data`（按 `xqyun_settings` 表的 key 组织）：

### 4.6 页面渲染聚合

`GET /api/v1/frontend/render/page?path=/about&locale=zh-CN` 响应 `data`：

```json
{
  "page": {
    "id": "1001",
    "group_id": "01J...",
    "locale": "zh-CN",
    "path": "/about",
    "name": "关于我们",
    "seo": { "title": "...", "description": "...", "keywords": [] },
    "blocks": [],
    "version": 3,
    "published_at": 1792375200,
    "published_by": "朱家伟",
    "alternates": {
      "zh-CN": "/about",
      "en": "/en/about-us"
    }
  },
  "nav": [],
  "site": {},
  "collections": {
    "news": [],
    "products": [],
    "cases": []
  }
}
```

- `nav` / `site` 的字段按 `NavItem` / `SiteConfig` 返回。
- `collections` 初版固定返回空数组，前台列表全部读取 `page.blocks` 中的自定义卡片。
- 请求未发布语言时返回 `40400`，前台据此渲染 404。

### 4.7 站点导航

初版不单独提供 `GET /api/v1/frontend/site/nav`：导航随 `GET /api/v1/frontend/render/page` 返回。

- `nav`：顶部一级菜单项（`[]NavItem`）。
- `site.header`：公告条、顶部按钮、语言入口、吸顶。
- `site.footer.columns`：页脚栏目与栏目内链接；`site.footer.bottom_links`：底部链接。
- `site.footer` 其余字段：订阅区、联系入口、大字标、状态提示。

前台按 `NavItem` / `SiteConfig` 字段合并渲染。

## 5. MySQL 表

### 5.1 初版建表范围

按接口依赖，初版建立 8 张表：

| 表 | 服务的接口 | 说明 |
| --- | --- | --- |
| `xqyun_users` | A1 / A4 | 后台账号 |
| `xqyun_pages` | P1–P8 / W1 | 页面草稿与线上内容；区块自定义卡片也在其中 |
| `xqyun_menus` | N1–N3 / W1 | 菜单容器 |
| `xqyun_menu_items` | N1–N3 / W1 | 菜单项与页脚链接 |
| `xqyun_settings` | N4 / N5 / W1 | 站点设置、头部 / 页脚配置 |
| `xqyun_form_submissions` | S1–S3 / W2 | 表单留言 |
| `xqyun_media` | M1–M5 | 素材库（视频 / 图片），本地磁盘存储 |
| `xqyun_publish_records` | P7 / P8 | 发布 / 下架记录 |

暂不建：

- `xqyun_contents`、`xqyun_categories`：初版不建内容库，列表数据在 `xqyun_pages` 的区块 JSON 中，二期需要内容库与详情页时再建。
- `xqyun_roles`、`xqyun_user_roles`、`xqyun_role_permissions`：初版不做 RBAC，登录后即为全部后台权限；二期改用 Casbin（角色表 `xqyun_roles` + 策略表 `xqyun_casbin_rule`，不建 `xqyun_user_roles` / `xqyun_role_permissions`），详见 [权限控制方案](./权限控制方案.md)。
- `xqyun_redirects`、`xqyun_audit_logs`：对应接口不在初版范围内，二期再补。
- `xqyun_refresh_tokens`：登录会话由 hertz-contrib/sessions 存 Redis，不建表。

### 5.3 初始化数据

建表后需要以下种子数据，否则登录与官网都无法启动：

1. **管理员账号**：`xqyun_users` 插入一条 `username = 'admin'` 的记录，`password_hash` 用 bcrypt 生成（调用 `auth.HashPassword`），禁止写明文；首次登录后修改密码。初版不做角色，这个账号拥有全部后台能力。
2. **菜单**：`xqyun_menus` 插入 `header`、`footer`、`footer_bottom` 三条记录。
3. **站点设置**：把 `admin/src/data/seed/settings.ts` 的内容写入 `xqyun_settings`，key 至少包含 `site_name`、`company_name`、`tagline`、`contact`、`brand`、`header`、`footer`、`socials`、`seo`、`copyright`、`icp`。
4. **页面**：写一次性导入脚本，把 `admin/src/data/seed/pages.*` 导入 `xqyun_pages`；页面发布态可以直接写入 `published_content`。现有 `/news`、`/products`、`/cases` 页面的数据源区块需要改成「自定义卡片」，不再导入内容库。

> 导入脚本建议放在 `service/cmd/seed` 或 `deploy/seed`，只运行一次，不进入常规启动流程。

## 6. 实施顺序

按依赖关系分 7 步，前一步完成并联调通过后再进入下一步。

### 第 1 步：数据库

1. 按 5.2 的表结构建立 8 张表（迁移文件或 GORM 模型）；登录会话存 Redis，不需要建表。
2. 执行初始化数据：管理员账号、菜单、站点设置。
3. 执行页面导入脚本，确认中英文页面齐全；内容列表区块改为自定义卡片。
4. 验收：表结构与主文档一致；`SELECT` 能读出页面、导航与设置。

### 第 2 步：认证

1. 实现 A1–A3。
2. 实现登录会话中间件：只校验 Session 是否有效，不做角色 / 接口权限校验。
3. 登录写入 `last_login_at`；退出 / 改密删除当前会话。
4. 验收：正确 / 错误密码、未登录、会话过期、退出后重新登录、改密后当前会话失效。

### 第 3 步：页面编排

1. 实现 P1–P8。
2. 页面保存、翻译、发布、下架全部在事务中完成。
3. 校验 `(locale, path)` 唯一；发布写 `xqyun_publish_records`。
4. 验收：后台页面列表 → 编辑 → 保存 → 重新打开 → 发布 → 下架全链路。

### 第 4 步：导航与站点配置

1. 实现 N1–N5。
2. `PUT /admin/menus/:code` 整体替换当前菜单条目；`PUT /admin/settings` 按完整对象保存。
3. 验收：顶部菜单、页脚栏目与链接、底部链接、公告条、顶部按钮、Logo、品牌色、收录开关都能保存并读回。

### 第 5 步：官网公开接口

1. 实现 W1–W3；W1 一次聚合页面、导航与站点。
2. 只读取已发布页面；`alternates` 只包含已发布语言。
3. `collections` 固定返回空数组；新闻 / 产品 / 案例列表读取页面区块的自定义卡片。
4. 表单提交落库并做限流。
5. 验收：中英文页面、自定义卡片列表、404、表单成功态。

### 第 6 步：表单留言管理

1. 实现 S1–S3，列表默认按提交时间倒序。
2. 状态只允许 `new` / `processing` / `done` / `spam`；标记后更新 `updated_at`。
3. 后台 `/#/submissions` 从 `localStorage` 改为调用 S1–S3；保留统计、筛选与详情抽屉。
4. 验收：列表、详情、状态标记、筛选与刷新后状态保持。

### 第 7 步：前后台接真实接口

1. `admin/src/services/auth.ts` 从本地演示账号改为调用 A1–A4；登录、刷新、登出与路由守卫使用真实令牌。
2. `admin/src/services/` 其他模块从 `localStorage` 改为 HTTP；保留 `preview.html` 本地渲染，草稿数据从 `GET /admin/pages/:id` 获取。
3. `frontend/services/` 从 mock 改为 `render/page` + `forms`；站点配置、导航与所有列表卡片都从 `render/page` 取。
4. 新闻详情路由 `frontend/pages/news/[slug].vue` 初版不接数据：可以移除、返回 404，或让新闻卡片的 `href` 指向外链 / 其他已编排页面。
5. 在中英文、桌面 / 平板 / 手机下回归。
6. 补齐 P1 的 sitemap / robots（如本期完成）。

## 8. 风险与应对

| 风险 | 影响 | 初版应对 |
| --- | --- | --- |
| 初版不做角色与权限 | 任何登录账号都能发布、改导航与站点配置 | 初版只创建一个管理员账号，不开放账号管理；二期用 Casbin 补角色与权限中间件（`xqyun_roles` + `xqyun_casbin_rule`，见 [权限控制方案](./权限控制方案.md)） |
| 内容库与详情页未上线 | 新闻 / 产品 / 案例只能靠页面自定义卡片手工维护，没有统一内容库与详情正文 | 初版明确列表使用自定义卡片；二期再建 `xqyun_contents` / `xqyun_categories`、内容 CRUD 与 `render/content` |
| 媒体库未上线，区块图片可能以 data URL 存进 JSON | 页面 JSON 膨胀、接口变慢 | 初版优先使用外部 CDN / 图床 URL；单张控制在 1600px WebP |
| 无预览 token | 预览只能在后台 iframe 内看 | 预览数据走后端草稿接口，不暴露公网预览地址 |
| 无乐观锁 | 多人同时编辑会互相覆盖 | 初版限制管理员人数；二期加 `version` 校验 |
| 无缓存 / CDN | 每次页面请求都读库 | 初版用索引与单次聚合查询；流量上来后按主文档加 Redis / ETag |
| 无审计查询 | 发布、删除无法在后台追溯 | `xqyun_publish_records` 先落库；二期补 `xqyun_audit_logs` 页面 |
| 中英文数据不同步 | 语言切换指向空内容 | 发布前检查另一语言状态；`alternates` 只输出已发布语言 |

## 9. 完成定义（Definition of Done）

满足以下全部条件，初版视为可上线：

1. 第 1–7 步全部完成，验收清单全部通过。
2. 数据库中只存在符合主文档结构的初版 8 张表；无临时表、无演示专用字段。
3. 后台与官网都不再读取 mock / `localStorage` 数据；官网不调用 `render/content`、`contents`、`categories`。
4. 中英文各完成一次「登录 → 编辑 → 保存 → 发布 → 官网访问」完整走查。
5. 发布、下架、404、受限页面（`noindex`）行为符合主文档的单语言发布规则。
6. 备份与回滚路径明确：数据库每日备份；发布覆盖线上内容，不保留历史版本，回滚依赖数据库备份。
