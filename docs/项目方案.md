> 当前进度：官网前台、管理后台与 Go 后端主要功能已完成并联调（页面 / 导航 / 站点配置、表单提交与留言、媒体素材库、管理员资料与改密、前台渲染）；新闻 / 产品 / 案例内容库与当前用户接口尚未实现；Docker 部署包已完成并在测试服务器完成部署验证。初版已于 2026-10-22 打 tag `v1.0.0` 发布。详见 1.4。

## 1. 项目概述

建设一个「后台配置、前台渲染」的公司官网：运营人员在管理后台通过区块化编辑器搭建页面、维护内容与图片，一键预览、发布；访客看到的是有品牌一致性、响应式、对搜索引擎友好的官网。

核心链路：

```
运营搭建页面（草稿） → 预览确认 → 发布（覆盖线上内容） → 前台/CDN 生效
```

### 1.1 核心目标

1. **运营自主**：日常改文案、换图、加栏目、调页面结构不需要开发介入。
2. **质量可控**：页面由预置区块组合而成，不会因为运营操作破坏品牌规范与响应式布局。
3. **发布安全**：草稿与线上隔离，发布前可完整预览，确认后立即生效。
4. **性能与 SEO**：首屏快、可被搜索引擎完整抓取、支持 sitemap / 301 / 结构化数据。
5. **中英双语**：一套后台管理两种语言的页面与内容，URL、导航、SEO 元信息按语言隔离。
6. **可扩展**：新增区块类型只需要在前端注册组件 + 声明 schema，后台表单自动生成。

### 1.2 MVP 范围

- 页面管理：列表、新建、复制、排序、草稿、预览、发布
- 区块化页面编辑器：区块增删、拖拽排序、属性配置、实时预览
- 预置区块库：首屏横幅、头部轮播（按图片 / 视频条件显示字段，视频支持海报封面）、富文本（TipTap 可视化编辑，支持图片上传 / 粘贴 / 拖入）、图文、特性列表、数据统计、产品列表、新闻列表、案例、合作伙伴、FAQ、CTA（主题底色或图片底图 + 遮罩）、联系表单、视频
- 内容管理：新闻 / 产品 / 案例（中英双语、分类、封面、富文本、SEO、发布状态）
- 媒体库：上传、压缩、选择、引用检查、双语 alt
- 导航菜单、页脚、站点设置（中英文案、Logo、联系方式、备案号、统计代码等）
- 表单与留言：提交入库、后台查看、邮件/webhook 通知
- 账号与权限：登录、角色、按钮级权限
- 前台：官网页面、内容详情页、404、响应式
- 多语言：中英双语站点、语言切换、前台 UI 文案国际化
- SEO：SSR 输出、meta/OG、hreflang、双语 sitemap、robots.txt、301 跳转
- 部署：开发 / 预发 / 生产三套环境

### 1.3 本期不做（明确边界）

- 像素级自由拖拽 / 绝对定位布局（用区块组合替代）
- 多站点、多租户
- 中英以外的第三种语言（语言机制可扩展，本期只交付中英）
- 会员体系、电商、支付
- 审批流（先用「编辑不能发布」的角色权限替代）
- 站内搜索、AI 生成内容（二期）
- 完整的可视化主题编辑器（本期站点配置只开放 Logo、品牌主色、页面底色、深色区块底色四个变量；字体、布局、组件级样式仍走代码）

## 2. 角色与权限

| 角色 | 典型人员 | 权限 |
| --- | --- | --- |
| 访客 | 外部用户 | 只读已发布内容，可提交表单（公开接口，不参与后台权限判定） |
| 内容编辑 `editor` | 市场/运营 | 内容、媒体、页面草稿的增改；**不能发布** |
| 发布管理员 `publisher` | 运营负责人 | 在编辑权限基础上，可预览、发布 |
| 系统管理员 | 技术/IT | 账号角色、站点设置、代码注入、审计日志；二期由 `super_admin` 承担 |
| 超管 `super_admin` | 项目负责人 | 全部权限 |
| 只读 `viewer` | 外部协作 / 验收 | 仅查看 |

权限按 **「URL 路由模板 + HTTP 方法」** 授权，不再编码独立的权限码。

**后端权限判定采用 Casbin**（`casbin/v3` + `gorm-adapter/v3`）：用户角色与「角色 → URL + 方法」策略存 MySQL 的 `xqyun_casbin_rule` 表，进程内判定；认证与授权拆成两个中间件，未登录返回 `40100`，登录但无权限返回 `40300`。判定对象取 `c.FullPath()` 路由模板与 `c.Method()`，超管用一条 `p, super_admin, /api/v1/admin/*, *` 覆盖全部后台接口；`/admin/me`、改资料、改密码走只挂认证的自由子组。前端按 `"METHOD 路由模板"` 字符串做菜单 / 按钮显隐，不作为安全边界。完整模型、角色策略清单与落地步骤见 [权限控制方案](./权限控制方案.md)。

> 当前后台已接登录与 JWT，未登录访问后台路由会跳回登录页；角色与权限（RBAC）**尚未实现**，所有后台接口只校验登录状态。`GET /admin/me` 与登录响应里的 `roles` / `permissions` 目前固定为空数组，接入 Casbin 后填充（`permissions` 为 `"METHOD 路由模板"` 列表）。

## 3. 总体架构

```
                         ┌─────────────────────────────┐
访客 / 运营 ── CDN/WAF ──│ Nginx                       │
                         │  /            → 前台 Nuxt SSR│
                         │  /admin       → 管理后台     │
                         │  /api         → Go API      │
                         │  /uploads     → 对象存储/CDN │
                         └──────────────┬──────────────┘
                                        │
                          ┌─────────────┴──────────────┐
                          │ Go API（无状态，可多副本）    │
                          │ 认证 / 内容 / 渲染 / 发布    │
                          └───┬──────────┬─────────────┘
                              │          │
                     ┌────────┴───┐  ┌───┴────────────┐
                     │  MySQL 8   │  │ 素材存储        │
                     └────────────┘  │ 本地磁盘 / OSS  │
                              │      └────────────────┘
                     ┌────────┴───┐
                     │ Redis(可选) │  缓存 / 限流 / 会话
                     └────────────┘
```

**当前实际形态（v1.0.0）**

```
frontend/（Nuxt 3 SSR） ── render/page、site/config、site/nav ──▶ service/（Hertz + MySQL 8 + Redis 7）
        │                                                        ▲
        └── 浏览器侧经 Nitro /api/backend/** 代理 ───────────────┘

admin/（Vite + Element Plus SPA） ── /api/v1/admin/**（Bearer JWT） ──▶ service/
        └─ iframe: preview.html（postMessage 推送草稿，仅后台内预览）
```

- 页面、导航、站点配置、素材与留言以 MySQL 为准；Redis 保存刷新令牌与渲染缓存分片。
- 浏览器只保存 Access Token / 用户信息（`xiaoque-admin-auth-v1`）与登录页设置（`xiaoque-admin-demo-v1`）。

### 3.1 设计原则

1. **内容与展示分离**：前台只认识「页面 JSON + 区块协议」，不关心内容存在哪。
2. **Schema 驱动**：区块的字段定义是唯一事实来源，后台表单和前台组件都由它派生，避免两边字段不一致。
3. **草稿与线上隔离**：草稿可随意改，线上只读最近一次发布的内容。
4. **契约共享**：最终目标是前后台共用 TypeScript 类型与区块 schema（`packages/` workspace 包），后端只做校验和存储，不参与字段渲染。**当前尚未抽取共享包**，`frontend` 与 `admin` 各有一份区块类型 / schema，改动协议时必须两边同步。
5. **先约定、后扩展**：MVP 用扁平区块（不嵌套容器），复杂布局靠预置组合区块解决。

### 4.1 关键决策：前台渲染方式（已确定为 Nuxt 3 SSR）

因为明确要求 SEO，前台采用 **Nuxt 3 服务端渲染（SSR）**，不使用纯 SPA：

- 前台 `frontend/` 使用 Nuxt 3（底层仍是 Vite + Vue 3 + TypeScript），服务端直出完整 HTML。
- 管理后台保持纯 Vite + Element Plus SPA，不需要 SSR。
- 部署时多一个 Node 运行时（Nuxt 服务），挂在 Nginx 后面；它与 Go API 都是无状态服务，可独立扩缩容。
- 已排除的方案：纯 Vite SPA（百度对正文抓取不稳定）、发布时全站 SSG（发布生效有延迟，且双语内容重建成本翻倍）。

**中英双语同样依赖 SSR**：每种语言的页面都要输出自己的 `<html lang>`、title/description、canonical 与 hreflang，服务端渲染是成本最低且最可靠的做法。

## 5. 核心设计

### 5.1 页面模型

一个页面 = 元信息 + 有序区块列表。区块只存类型和属性，不存 HTML 结构。

```json
{
  "id": "pg_001",
  "translation_group_id": "tg_001",
  "locale": "zh-CN",
  "path": "/about",
  "name": "关于我们",
  "status": "draft",
  "seo": {
    "title": "关于我们 - XX 公司",
    "description": "...",
    "keywords": ["..."]
  },
  "blocks": [
    { "id": "b_01", "type": "hero", "props": { "title": "...", "image": "media_123" } },
    { "id": "b_02", "type": "rich-text", "props": { "content": "<p>...</p>" } },
    { "id": "b_03", "type": "news-list", "props": { "title": "新闻动态", "limit": 6 } }
  ]
}
```

- 默认语言（zh-CN）URL 无前缀：`/about`；英文带 `/en` 前缀：`/en/about`。
- 英文页可以使用独立 slug（如 `/en/about-us`），两种语言通过 `translation_group_id` 配对。
- 内容详情页按类型配置前缀（如 `/news/{slug}`、`/en/news/{slug}`、`/products/{slug}`）。
- 保留路径：`admin`、`api`、`preview`、`uploads`、`assets`、`en` 等，禁止作为页面 slug。
- 发布时把当前草稿按语言写入 `published_content`，覆盖线上内容，不保留历史版本。

> 后台已按本节 API 模型映射：`groupId`、`locale: 'zh' | 'en'`、`status: 'draft' | 'published'`，草稿与发布内容保存在 MySQL（`xqyun_pages`），本地只保留登录会话与登录页设置。

### 5.2 区块协议（Block Schema）

每个区块类型在前端声明一份 schema，后台据此自动生成表单，前台据此渲染。

**字段类型**

| 类型 | 用途 | 后台控件 |
| --- | --- | --- |
| `text` / `textarea` | 单行 / 多行文本 | el-input |
| `richtext` | 富文本 | TipTap 3（已实现；支持标题、列表、引用、代码块、链接、图片） |
| `number` | 数字 | el-input-number |
| `switch` | 开关 | el-switch |
| `select` | 枚举 | el-select |
| `color` | 颜色 | el-color-picker |
| `image` / `images` | 单图 / 多图 | 素材库选择器（支持排序）；页面只保存素材 URL |
| `link` | 链接 | 页面 / 内容 / 外链选择器 |
| `date` | 日期 | el-date-picker |
| `repeater` | 可重复条目 | 可增删排序的子表单 |
| `group` | 分组 | 折叠面板 |
| `collection` | 数据源 | 内容类型 + 筛选 + 排序 + 条数 |
| `html` | 自定义代码（旧版兼容） | 不再出现在区块库；旧数据加载时自动迁移为 `richtext` |

**规则**

- 字段支持 `required`、`maxLength`、`pattern`、默认值、帮助文案。
- 字段支持 `visibleWhen`（按同级字段值条件显示，例如头部轮播只在内容类型为图片时显示图片字段、为视频时显示视频地址与封面）与 `uploadOnly`（只能上传、不给内置图形选项）。
- Schema 带 `version`，字段改名/删除时提供迁移函数，避免历史页面失效。
- 前台渲染器通过 `type → 组件` 映射；遇到未知类型时降级为占位并记录告警，不白屏。
- 区块库（MVP）：`hero`、`rich-text`、`image-text`、`features`、`stats`、`products`、`news-list`、`cases`、`partners`、`faq`、`cta`、`contact-form`、`video`；另已实现 `hero-carousel`（头部轮播）。旧版 `html` 区块保留类型用于数据迁移，但 `hidden` 不再出现在区块库。
- **图片字段**：`image` 字段可切「内置图形 / 素材库」；素材库弹窗负责上传与选择，页面只保存素材 URL（`xqyun_media`）。纯图片场景（CTA 底图、视频封面）使用 `uploadOnly`，只显示素材库、不展示内置图形。富文本插图同样先上传素材库再插入 URL。
- **行动号召（CTA）**：背景可在「主题底色」与「素材库图片」之间切换；图片模式支持 0–90 的遮罩强度，文字自动反白，并在有图时隐藏内置装饰图形。
- **头部轮播**：内容类型为图片时只显示图片字段；为视频时显示视频地址与可选海报封面（作为 `<video poster>`）。原「色调」字段已删除（只对内置图形生效，容易误解）。
- **数据源区块可被自定义卡片覆盖**：`products`、`news-list`、`cases` 支持 `items` 重复项（图片、标签、标题、摘要、要点、按钮文案、跳转链接）。`items` 非空时按自定义卡片渲染；为空时回退为自动读取已发布内容。「显示条数」同时限制两种来源。这样运营既能复用内容库，也能为某个页面单独排卡片。
- **客户案例详情**：点击案例卡片打开详情弹层，「详情补充说明」「详情按钮文案 / 链接」在自动读取和自定义卡片两种模式下都生效。「显示条数」同时限制两种来源；自定义卡片的链接展示为弹层内的「查看完整案例」按钮。

**尚未实现**

### 5.4 前台渲染

> 当前实现：`frontend/` 的页面通过 `render/page` 取数据，头部 / 页脚通过 `site/config` 与 `site/nav` 取配置，区块组件按接口返回的 props 渲染；联系表单提交到 `POST /frontend/forms/contact/submissions`；新闻 / 产品 / 案例没有独立内容库，列表使用页面区块的「自定义卡片」。后台草稿由 `admin/preview.html` 使用同一套区块组件渲染。

1. 前台请求聚合接口 `GET /api/v1/frontend/render/page?path=/about&locale=zh-CN`。
2. 服务端一次返回：该语言已发布页面内容 + 该语言导航/站点设置 + 按语言过滤的区块数据（新闻/产品列表等）。
3. 前台 `BlockRenderer` 按 `block.type` 映射组件并渲染。
4. 数据源由服务端解析，避免前台为每个区块发一次请求，也便于缓存。
5. 详情页通过 `GET /api/v1/frontend/render/content?type=news&slug=xxx` 获取。

**降级策略**

- 未知区块：跳过并输出注释告警（生产不报错、不白屏）。
- 图片缺失：使用占位图。
- 数据源为空：显示区块的空状态或整体隐藏（schema 可配置）。

### 5.5 预览与发布

**预览**

- 后台通过 iframe 加载 `admin/preview.html`，用 `postMessage` 推送页面、语言、内容集合与站点设置；编辑器改字段后防抖刷新。预览内的站内链接被禁用，避免在 iframe 中跳走。
- 预览只在浏览器内完成，不签名、不经过 Go 接口，也不读取 `render/page`。

**发布**

1. 校验页面与区块数据。
2. 用当前草稿覆盖 `published_content`，`version + 1`。
3. 更新 `status`、`published_at`，写入 `xqyun_publish_records`。
4. 删除该页与同翻译组的 Redis 渲染缓存（导航、站点配置分片不受影响）；缓存删除失败不影响发布结果。
5. 写入审计日志。

**原子性**

- MVP 按页面独立发布；站点设置/导航修改即时生效。
- 二期可引入「站点发布批次」，把所有待发布变更一次性原子上线。

### 5.6 缓存与生效

**当前实现**

`GET /api/v1/frontend/render/page` 的聚合结果按三个分片缓存在 Redis：

| 分片 | Redis key | 内容 |
| --- | --- | --- |
| 页面 | `xqyun:render:page:{locale}:{path}` | 页面 SEO、区块、版本、alternates、发布人 |
| 导航 | `xqyun:render:nav:{locale}` | 顶部导航、页脚栏目、底部链接 |
| 站点配置 | `xqyun:render:site:{locale}` | Logo、品牌色、页面底色、收录开关等 |

- 配置在 `config.yaml` 的 `render_cache`：`enabled` 默认开启，`ttl` 默认 10 分钟。
- TTL 只是兜底。后台发布、下架、删除、修改路径、保存导航、保存站点配置时都会主动删除对应分片。
- Redis 未启用或读写异常时自动回源数据库，请求不受影响。
- 后台草稿预览走 `preview.html` + `postMessage`，不经过 `render/page`；预览里看到的改动不代表线上已生效。

**后台操作 → 前台什么时候变**

| 后台操作 | 前台变化 | 说明 |
| --- | --- | --- |
| 编辑页面、自动保存或手动「保存草稿」，路径不变 | **不变** | 只写 `draft_content`，线上仍是上次发布的内容；后台预览能看到草稿 |
| 保存草稿时修改页面路径 | **立即** | 旧地址失效、新地址生效，同翻译组的 hreflang 同步更新 |
| 发布页面 | **立即** | 草稿覆盖线上内容，同时删除该页与同翻译组的缓存 |
| 下架页面 | **立即** | 该地址返回 404 |
| 删除页面 | **立即** | 该地址返回 404 |
| 保存顶部导航 / 底部导航 | **立即** | 所有页面的头部、页脚一起更新 |
| 保存站点配置（Logo、主色、底色、收录开关等） | **立即** | 所有页面生效；收录开关同时影响 robots |
| 修改管理员显示名称 | 最多 10 分钟 | 只影响 `published_by` 文案，页面内容不变 |
| 直接改数据库 / 运维脚本 | 最多 10 分钟 | 绕过后台不会触发主动失效，等 TTL 过期 |

**一句话记**

- 只保存草稿：线上不变。
- 发布、下架、保存导航、保存站点配置：立即生效。
- 改页面路径：立即生效，不需要发布。
- 绕过 Go 接口直接改库：最多等 10 分钟。

**后续优化**

- 增加 `ETag` / `If-None-Match`（基于页面 `version`）与 CDN 缓存、主动 purge。
- 内容库上线后，为 `collections` 增加按类型 + 语言的分片缓存。

### 5.8 多语言设计（中英）

**URL 策略**

| 语言 | URL 形式 | 示例 |
| --- | --- | --- |
| 中文（默认） | 无前缀 | `/about`、`/news/xxx` |
| 英文 | `/en` 前缀 | `/en/about-us`、`/en/news/xxx` |

- 不做基于浏览器语言的强制 302 跳转（对 SEO 不友好）；首次访问可显示语言推荐条，由用户选择。
- 语言切换只跳转到**已翻译且已发布**的对应页面；未翻译时退回该语言首页或隐藏入口。

**内容模型**

- 页面、内容、分类都按语言各存一条记录，`translation_group_id` 把同一实体的中英版本关联起来。
- 每个语言版本独立草稿、独立发布，互不覆盖。
- 区块结构可一键从中文复制到英文，只复制结构与不可翻译字段，文本留空待翻译。
- 数据源区块（新闻列表、产品列表等）自动按当前语言过滤，英文页不会显示中文内容。
- 导航、页脚、站点设置、媒体 alt 文案均支持按语言配置。

**单语言发布规则**

- 中文发布、英文未发布时：中文页面正常 SSR 返回 200；英文 URL 返回 404 + `noindex`，不暴露英文草稿。
- 英文发布、中文未发布时同理；两边发布互不影响，不做级联发布。
- 语言切换只指向已发布的译文；另一语言未发布时隐藏切换入口，或退回该语言首页。
- hreflang / `alternates` 只包含已发布的语言版本，不指向 404 地址；`x-default` 指向默认语言已发布版本。
- sitemap 只列出已发布页面和内容，未发布语言不会出现。
- 后台草稿预览不受发布状态限制，只在后台 iframe 内展示，不产生可被搜索引擎索引的地址。
- 之后发布另一语言时，该语言立即上线，语言切换与 hreflang 同步更新。

**后台工作流**

- 编辑器顶部提供「中文 / English」语言 Tab，展示翻译状态：未创建 / 草稿 / 已发布。**已实现**（切换目标语言时自动创建配对草稿）。
- 「创建英文版本」：复制页面结构与区块顺序，生成配对的英文草稿。**已实现**：可翻译文本清空，图片与链接保留。
- 发布支持「发布当前语言」（已实现）；「发布全部语言」待实现。发布前提示另一语言是否存在未发布修改。
- 翻译文案由人工录入；二期可接翻译服务，或提供 XLSX 导入导出给翻译团队。

**前台**

- UI 固定文案（按钮、表单提示、分页等）走 i18n 词条文件。
- `<html lang>`、日期/数字格式按语言切换。
- 英文内容缺失时不输出半截中文；入口隐藏或跳转英文首页，避免中英混排与重复内容。

**SEO**

- 每个已发布语言页面输出自引用 canonical；hreflang 只包含已发布语言，`x-default` 指向默认语言的已发布版本。
- sitemap 按语言列出全部已发布 URL，并声明语言替代关系。
- 中英文分别配置 title、description、OG 图与结构化数据。
- 英文使用独立、可读的 slug，不使用拼音或无意义 ID。

## 7. 数据模型（核心表）

> 完整的字段、类型、索引与 JSON 结构见 [MySQL数据库表设计](./MySQL数据库表设计.md)。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `xqyun_users` | id, username, password_hash, name, email, mobile, status, last_login_at | 后台账号 |
| `xqyun_roles` | code, name, description, is_system | 角色展示信息（中文名、内置角色保护）；权限关系不存这里 |
| `xqyun_casbin_rule` | ptype, v0 … v5 | Casbin 策略表：`p` = 角色 → URL 模板 → 方法，`g` = 用户 → 角色；由 gorm-adapter 读写 |
| `xqyun_pages` | id, translation_group_id, locale, path, name, draft_content(JSON), published_content(JSON), version, updated_at | 页面主表；`(locale, path)` 唯一 |
| `xqyun_contents` | id, translation_group_id, type, slug, locale, title, summary, cover_media_id, body_html, body_json, category_id, status, published_content(JSON), version, published_at, seo(JSON) | 新闻/产品/案例统一表；保存草稿与线上内容，`type` + `locale` 区分 |
| `xqyun_categories` | id, translation_group_id, type, slug, locale, name, parent_id, sort | 分类按语言配对 |
| `xqyun_media` | id, filename, storage_key, url, mime, size, width, height, sha256, alt(JSON), deleted_at | 媒体库；alt 存 `{"zh-CN": "...", "en": "..."}` |
| `xqyun_menus` / `xqyun_menu_items` | code, name / menu_id, parent_id, label(JSON), link_type, link_value, sort, visible | 导航；菜单文案按语言 |
| `xqyun_settings` | key, locale, value(JSON), updated_at | `locale` 为空表示全局配置 |
| `xqyun_form_submissions` | id, form_key, page_id, data(JSON), ip, user_agent, status, created_at | 留言 |
| `xqyun_redirects` | id, from_path, to_path, status_code | 301 |
| `xqyun_audit_logs` | id, user_id, action, target_type, target_id, detail(JSON), ip, created_at | 审计 |
| `xqyun_publish_records` | id, target_type, target_id, status, operator_id, created_at | 发布 / 下架记录 |

设计说明：

- 页面/内容用 JSON 存结构化数据，避免为每种区块建表，扩展成本低。
- 所有业务表带 `created_at` / `updated_at`；删除采用软删除（`deleted_at`），防止误删后无法恢复。
- 多语言用 `translation_group_id` 配对，同一组内每种语言一条记录；本期固定 `zh-CN` / `en`，新增语言只需加 `locale` 值，不迁移表结构。
- 唯一约束按语言维度：页面 `(locale, path)`，内容 `(locale, type, slug)`，分类 `(locale, type, slug)`。
- 草稿与发布都按语言独立，互不覆盖；发布覆盖线上内容，不保留历史版本。

## 8. API 设计

> 完整的接口清单、请求 / 响应示例与 Go 数据结构见 [Go后端接口设计](./Go后端接口设计.md)。

### 8.1 约定

- 前缀：官网前台 `/api/v1/frontend/`，管理后台 `/api/v1/admin/`。
- 认证：`Authorization: Bearer <access_token>`。
- 语言：所有公开接口接受 `locale` 参数（`zh-CN` / `en`，默认 `zh-CN`）；后台接口按记录自带的 `locale` 工作。
- 统一响应：`{ "code": 0, "message": "ok", "data": {...} }`；所有响应 HTTP 200，`code = 0` 表示成功，失败按 `code` 判断。`request_id` 作为后续增强项。
- 错误码：`40000` 参数错误、`40100` 未登录 / 令牌无效、`40300` 无权限、`40400` 资源不存在、`50000` 服务端错误；后续扩展 `40001`（字段校验）、`40101`（令牌过期）、`40900`（资源冲突）、`42900`（限流）、`50001`（下游依赖失败）。
- 时间与 ID：时间字段统一 Unix 时间戳（秒，Go `int64`，JSON number），`0` 表示未设置；ID 在 JSON 中统一用字符串，避免大整数精度丢失。
- 分页：`?page=1&page_size=20`，返回 `{ items, total, page, page_size }`。
- OpenAPI 3 文档自动生成，并生成前端 TypeScript 类型，杜绝手写接口类型。

### 8.2 官网前台接口（公开）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/frontend/render/page?path=&locale=` | 页面渲染数据（页面+导航+站点+数据源） |
| GET | `/frontend/render/content?type=&slug=&locale=` | 内容详情 |
| GET | `/frontend/contents?type=&category=&locale=&page=` | 内容列表（按语言过滤） |
| GET | `/frontend/categories?type=&locale=` | 分类列表（前台筛选器） |
| GET | `/frontend/site/config?locale=` | 站点设置（脱敏，按语言返回可翻译项） |
| GET | `/frontend/site/nav?locale=` | 导航（按语言返回文案） |
| POST | `/frontend/forms/{key}/submissions` | 表单提交 |
| GET | `/sitemap.xml` / `/robots.txt` | 由后端或静态生成 |

### 8.3 管理后台接口

| 模块 | 主要接口 |
| --- | --- |
| 认证 | `POST /admin/auth/login`、`/refresh`、`/logout`、`GET /me` |
| 页面 | `GET/POST /admin/pages`、`GET/PUT/DELETE /admin/pages/:id`、`POST /:id/publish` |
| 内容 | `GET/POST /admin/contents`、`GET/PUT/DELETE /admin/contents/:id`、分类 CRUD |
| 媒体 | `POST /admin/media/upload`、`GET /admin/media`、`DELETE /admin/media/:id` |
| 导航/设置 | `GET/PUT /admin/menus`、`GET/PUT /admin/settings` |
| 表单 | `GET /admin/submissions`、`PUT /admin/submissions/:id/status`、`GET /export` |
| 系统 | 用户/角色 CRUD、`GET /admin/audit-logs` |

页面与内容接口均支持 `?locale=` 筛选；`POST /admin/pages/:id/translate` 用于从某一语言复制区块结构、生成另一语言的配对草稿。

## 10. 安全设计

- **密码**：bcrypt 加盐哈希（密码上限 72 字节）；登录失败次数限制与延迟。
- **令牌**：Access Token 15 分钟（本地保存），Refresh Token 7 天（HttpOnly + Secure + SameSite=Lax Cookie），刷新时轮换；登出/改密吊销。
- **权限**：后端中间件统一鉴权。登录态由 `AdminAuth` 校验，授权由 Casbin 按 `(用户, 路由模板, HTTP 方法)` 判定（策略存 `xqyun_casbin_rule`，无匹配策略默认拒绝），前端按钮显隐只是体验优化。详见 [权限控制方案](./权限控制方案.md)。
- **XSS**：富文本入库前用 bluemonday 白名单清洗；不再提供自定义 HTML 区块，旧版区块加载时迁移为富文本；前台输出转义；配置 CSP（允许统计脚本白名单）。
- **上传**：类型白名单（jpg/png/webp/gif/pdf 等）、大小限制、随机文件名、图片重新编码（剥离元数据）、禁止/清洗 SVG、上传文件独立域名。
- **预览**：只在后台 iframe 内渲染，不提供公网预览地址，不经过前台接口。
- **接口**：登录与表单接口限流；CORS 白名单；请求体大小限制。
- **审计**：登录、发布、删除、权限变更全部留痕（操作人、IP、对象、摘要）。
- **其他**：密钥只走环境变量；依赖定期扫描；生产关闭调试信息；数据库与对象存储不暴露公网。

## 11. 部署与运维

### 11.1 环境

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| dev | 本地开发 | 本地 MySQL 8 + Redis；素材存 `service/uploads` |
| staging | 验收/预发 | 独立数据库，近似生产配置 |
| prod | 线上 | MySQL 8 + Redis；对象存储 / CDN 待接入 |

### 11.2 部署形态（当前实现）

Docker Compose 编排（`deploy/docker/xqyun/docker-compose.yml`）：

- `gateway`：唯一的 Nginx（`nginx:1.27-alpine`），80 端口统一入口，同时提供管理后台静态文件
- `frontend`：Nuxt 3 SSR（`node:22-alpine` 挂载 `.output`）
- `backend`：Go 后端（`alpine:3.22` 挂载 Linux 二进制）
- `mysql`：MySQL 8
- `redis`：Redis 7，AOF 持久化
- `migrate`：golang-migrate 一次性任务，执行完退出，后端等待其成功后才启动

特点：

- 不构建自定义镜像，直接用官方镜像挂载 `data/release` 下的构建产物；
- 管理后台、前端、后端都不需要源码即可部署；
- 数据统一落 `data/{mysql,redis,uploads,logs}`，Nginx 配置在 `data/nginx/conf`；
- MySQL 首次初始化时按 `MYSQL_DATABASE` 自动建库并执行 `init.sql`，表结构由 `migrate` 创建。

生产建议：

- API 无状态，流量上来后可水平扩容；
- 数据库使用云托管并开启每日备份；
- 图片与静态资源走 CDN / 对象存储；
- Nginx 终止 TLS，HTTP/2 + Brotli，并把 `JWT_COOKIE_SECURE` 设为 `true`；
- 数据库迁移在发布流程中作为独立 job 执行，先迁移后切流量。

### 11.3 CI/CD

- CI：Go（`golangci-lint`、单测）、前端（`eslint`、`vue-tsc`、单测）、构建镜像。
- CD：staging 自动部署；prod 手动审批。
- 发布后自动检查 `/healthz` 与核心页面状态码。

### 11.4 可观测与备份

- 结构化 JSON 日志 + 请求 ID；记录慢请求（当前使用 Hertz accesslog，生产写 `data/logs/app.log` 并按大小轮转）。
- 健康检查：当前为 `GET /ping`；`/healthz`、`/readyz` 二期补充。
- 监控：5xx 比例、P95 延迟、证书到期、磁盘、备份结果。
- 备份：数据库每日全量 + 保留 30 天；对象存储开启版本控制；每季度做一次恢复演练。
- Docker 部署数据都在 `deploy/docker/xqyun/data`，备份时至少包含 `data/mysql`、`data/uploads` 和 `.env`。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 区块 schema 设计不足，后期扩展困难 | 高 | 字段类型覆盖常见场景；schema 版本化 + 迁移函数；旧版 HTML 区块迁移为富文本 |
| 前台纯 SPA 导致 SEO 差 | 高 | 尽早确定 SSR/SSG 方案（见 4.1） |
| 发布后缓存不一致 | 中 | 写操作主动失效 Redis 分片；TTL 兜底；后续补 ETag / CDN purge |
| 运营误操作 | 中 | 草稿/发布分离、发布前校验、审计 |
| 富文本 XSS | 高 | 服务端白名单清洗 + CSP |
| 图片过大拖慢页面 | 中 | 上传压缩、WebP/AVIF、懒加载、CDN |
| 权限设计过于复杂 | 低 | 先落地 4 个角色 + URL / 方法策略，不引入复杂规则引擎 |
| 中英内容不同步或漏翻译 | 中 | 翻译状态标识、发布前提示、语言切换只指向已发布译文、定期巡检 |
| 需求蔓延（自由拖拽/第三种语言/审批流） | 中 | 明确 MVP 边界，进入二期排期 |

## 附录 A：为什么选区块化而不是自由拖拽

| 维度 | 区块化（本方案） | 自由拖拽 |
| --- | --- | --- |
| 上线速度 | 快，组件即能力 | 慢，需要布局引擎 |
| 响应式质量 | 每个区块自带移动端规则，稳定 | 需要运营逐屏适配，容易错位 |
| 品牌一致性 | 由组件保证 | 依赖运营自觉 |
| 运营学习成本 | 低（选区块、填表单） | 高（像用设计软件） |
| 后期维护 | 新增区块即可扩展 | 自由布局数据难以治理 |
| 适用场景 | 公司官网、营销页 | 建站工具、设计自由度极高的产品 |

普通页面由区块组合覆盖；特殊版式可先用富文本区块（支持图片）兜底。旧版 `html` 区块仅保留用于历史数据迁移，不再对编辑者开放，避免 XSS 与样式失控。
